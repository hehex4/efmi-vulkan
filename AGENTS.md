# EFMI Vulkan - working agreement

- When resuming work, read `.ai-memory/CURRENT_STATE.md` and `.ai-memory/TASKS.md` first; goal, architecture, constraints and earlier decisions are in the other memory documents, and the full plan is `docs/plan.md`.
- Modify only this project, `F:\efmi vulkan`. The one other location this project owns is `F:\vulkan`, which holds the Vulkan headers (and the Vulkan SDK if the user installs it there). The EFMI/XXMI installation, the launcher configuration, `d3d11.dll`, `d3dx.ini`, `Core`, existing mods, the game installation and the sibling project `F:\EFMI MCP` are read-only.
- The layer is never loaded into the real game without the user saying so on the spot. Gate G1 carries a risk for the account, and which account is used is the user's decision. No work is ever done to evade, hide from or fight the anti-cheat; if loading is blocked, the project stops.
- System-wide state is not changed without being asked: no layer registration in the registry, no environment variables outside a test's own child process, no installer run on the user's behalf.
- Keep "builds", "loads in the sandbox", "captures in the sandbox", "loads in the real game", "data captured in the real game" and "verified on a real character" strictly apart. A sandbox result must not stand in for the real game, and a historical result must not stand in for this round.
- After changing the layer, build it and run the regression suite (`sandbox/run_all.py`). A DLL stays loaded in a process until it exits; a successful build on disk does not mean a running process has the new version.
- Commit after every change (user, 2026-10-11): once a change has passed its verification, review the diff, sync the project memory and create a local Git commit unprompted. No remote is configured; nothing is pushed until the user names a repository. Build output, captures and game assets are not committed.
- Before ending a round of work, update the current state, the tasks and the session log; when there is a new decision or problem, update the corresponding document as well. Record evidence, the scope of verification and what remains; do not paste long logs.
- Everything in this workspace is written in English and contains no Chinese characters: file names, documents, project memory, code comments, test data and commit messages (user, 2026-10-11). A string that has to match text which another tool produces in a different script is spelled with `\u` escapes. `scripts/check_text.py` checks this and is part of the regression suite. Conversation with the user is in Chinese; that concerns the chat only, not the files.
- Windows opened by tests (the sandbox program and the like) go on the secondary screen and do not take the focus (carried over from the EFMI MCP agreement, user, 2026-10-08).
